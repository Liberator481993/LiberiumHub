2. FEATURES CONFIRMED IN SOURCE

- Role ESP maps Hero to yellow, Sheriff to blue, Murderer/Killer/Zombie to red, and Innocent/Survivor to green.
- Outline and Fill are configured independently through Highlight transparency values.
- Loot ESP is deliberately candy-only by name matching; coin collection remains a separate AutoFarm system.
- AutoPickup and AutoFarm are separate trackers; AutoFarm takes priority when both settings are enabled.
- UI scaling is recalculated after Main, Side, and Content are created (the upd() call follows Content creation).
- UI cleanup disconnects the camera viewport connection.
- LootTracker uses a bounded tracker count (150) and batched initial scanning (500 instances per yield).

3. RISKS / ITEMS TO TEST

A. Server Hop compatibility — MEDIUM
ServerHop uses HttpService:RequestAsync from the client. Roblox's standard HttpService request methods are generally server-side capabilities; this call may fail in a normal client context and the source itself reports an HTTP-blocked failure. Verify on the target Delta build. Rejoin Server uses TeleportService separately and should be tested independently.

B. Loot ESP name matching — LOW
getTrackedColor accepts any BasePart/Model whose lowercased name contains "candy", except a few explicitly excluded container names. This may include decorative or helper objects whose names contain "candy". Test on active MM2 maps and tighten the allowlist only if false positives are observed.

C. Runtime/syntax validation — NOT VERIFIED
No Roblox Studio or Delta execution was available in this audit. Static inspection cannot establish that every API call, touch interaction, teleport, UI gesture, or game-specific object path works in a live MM2 round.

D. Game-side behavior — NOT VERIFIED
RemoteFunction role-data discovery and touch-based pickup behavior depend on the live game hierarchy and server behavior. A local client-side indicator is not proof that the server accepted a pickup.
